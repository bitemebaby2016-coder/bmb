# Plan: Fix CI Migration 210 Runtime Verification Failure

## Problem
CI "Apply migrations 001-123 (inventory mode)" fails at migration 210:
```
supabase/migrations/210_rider_my_deliveries_round_fix.sql#L678
ERROR: ERR_STORE_CLOSED: ร้านปิดแล้วตามเวลาที่แอดมินตั้ง (10:00–22:00) น.
```

## Root Cause
Migration 210's runtime verification DO block creates a fixture order (line 632-642). This INSERT fires `trg_shop_hours` trigger (migration 184) which calls `enforce_shop_hours()`. That function reads `business_settings.operating_hours` and checks if store is open for the order's mode. CI runs at a time outside 10:00-22:00 Bangkok → trigger raises `ERR_STORE_CLOSED`.

## Fix
In migration 210's `$verify_runtime$` DO block, before creating the fixture order, ensure `business_settings.operating_hours` has the store open:

```sql
-- 0b. ensure store is OPEN for fixture test (CI may run outside 10:00-22:00 Bangkok)
INSERT INTO public.business_settings (key, value, created_at, updated_at)
VALUES ('operating_hours', '{"same_day_open": true, "pre_order_open": true, "morning_open": true, "midday_open": true, "evening_open": true}'::jsonb, NOW(), NOW())
ON CONFLICT (key) DO UPDATE SET value = EXCLUDED.value, updated_at = NOW();
```

Place this right after the tenant INSERT (around line 610).

## Files to Change
- `supabase/migrations/210_rider_my_deliveries_round_fix.sql` — add the business_settings upsert in the `$verify_runtime$` DO block

## Notes
- This is a **test-only fix** — the business_settings row is rolled back with the fixture (entire DO block runs in transaction that rolls back)
- Does not affect production behavior
- Similar pattern used in other migrations for test isolation
