# ✅ Checklist ทดสอบจริงบน Production — Bite Me Baby (คู่มือ Owner)

**วันที่จัดทำ:** 2026-10-19 · **เว็บจริง:** https://biteme-baby.com
**หลักการระหว่างทดสอบ:** ทุกยอดเงินให้เทียบกับ "คำสั่งซื้อที่จ่ายจริงแล้ว (paid)" เท่านั้น · สถานะพิมพ์ต้องกดยืนยันเอง · ถ้าจุดไหนไม่ตรงตามที่เขียนไว้ = พบบั๊ก ให้จดเวลา+หน้าจอ+หมายเลขออเดอร์ไว้ได้เลย

## 0) เตรียมตัวก่อนเริ่ม (5 นาที)

- [ ] เข้า https://biteme-baby.com/admin ด้วยบัญชี Owner → เห็นแดชบอร์ดปกติ
- [ ] เปิด GitHub → Actions → `daily-backup` → เห็น run ล่าสุด **สีเขียว** (ถ้ายังไม่มี ให้กด Run workflow 1 ครั้ง — ดูข้อ 8)
- [ ] บนมือถือ 1 เครื่อง (ลูกค้า) + คอม 1 เครื่อง (แอดมิน/POS) + เครื่องพิมพ์ที่ต่อกับคอม

## 1) 🛵 Customer Pickup — รับที่ร้าน (ฟีเจอร์ใหม่)

- [ ] **1.1** มือถือเข้าเว็บ → เพิ่มสินค้าลงตะกร้า → ไปหน้าชำระเงิน
- [ ] **1.2** เลือกวิธีรับอาหาร: **"รับที่ร้าน (Pickup)"** → ค่าจัดส่งแสดง **0 บาท** ทันที
- [ ] **1.3** เลือก**ช่วงเวลารับ**อาหาร (ช่วงเวลาที่แสดงต้องมาจากเวลาทำการที่ตั้งไว้) → กรอกชื่อ/เบอร์
- [ ] **1.4** ชำระเงินตามวิธีที่ร้านเปิด (โอน/เงินสด) → ยืนยันคำสั่งซื้อ
- [ ] **1.5** หน้ายืนยันคำสั่งซื้อแสดง **"รหัสรับอาหาร 6 หลัก"** ชัดเจน + ยอดรวมไม่มีค่าจัดส่ง
- [ ] **1.6** ฝั่งแอดมิน: มีออเดอร์นี้ในรายการ (วิธีรับ = รับที่ร้าน) + เปลี่ยนสถานะไป `พร้อมส่งมอบ`
- [ ] **1.7** เปิดหน้า POS → แถบ "รับที่ร้าน" → ใส่รหัส 6 หลัก → ระบบ**ตรวจรหัสถูกต้อง** → กดรับมอบ → สถานะเป็น `จัดส่งแล้ว` + บันทึก**เวลาที่ลูกค้ารับจริง**
- [ ] **1.8** ลองใส่**รหัสผิด** → ระบบปฏิเสธ ไม่ให้ส่งมอบ
- [ ] **1.9** ฝั่งลูกค้า: หน้ารายละเอียดออเดอร์แสดงรหัส+สถานะอัปเดตถูกต้อง

## 2) 🛵 การสั่งแบบ Delivery (ของเดิม — ต้องไม่พัง)

- [ ] **2.1** สั่งแบบ "จัดส่ง" 1 ออเดอร์ → ค่าจัดส่งคิดตามจริง (ไม่ใช่ 0) → ใส่ที่อยู่/ปักหมุดแผนที่ได้
- [ ] **2.2** เส้นทางออเดอร์เดิมครบ: `รับออเดอร์ → ยืนยัน → กำลังทำ → พร้อมส่ง → จัดส่งแล้ว`
- [ ] **2.3** ระบบ**ไม่ยอม**ข้ามสถานะผิดกฎหมาย (เช่น ข้ามจาก `รับออเดอร์` ไป `จัดส่งแล้ว` ตรง ๆ)
- [ ] **2.4** ปุ่มคืนเงิน (ถ้ามีการคืน) ทำงานเฉพาะแอดมิน + เงินที่คืนถูกหักออกจาก "เงินที่ได้รับ"

## 3) 💵 Web POS เงินสด + เปิด/ปิดกะ

- [ ] **3.1** เข้า `/admin/pos` → **เปิดกะ** ใส่เงินเริ่มต้น (float) → เห็นสถานะกะเปิดอยู่
- [ ] **3.2** เลือกสินค้าจากตารางสินค้า (มีรูป/ราคา) → เพิ่มลงตะกร้า → ขายเป็น**เงินสด** → ระบบตัดสต็อก/สร้างออเดอร์ทันที
- [ ] **3.3** ขายแบบ **"รอชำระ" (bill)** แล้วมา**ยืนยันชำระทีหลัง** → ยอดขึ้นเป็น paid เมื่อยืนยันเท่านั้น
- [ ] **3.4** แตะสินค้าเดิมซ้ำ = เพิ่มจำนวน (ไม่ใช่ออเดอร์ใหม่) — กดค้าง/ปุ่มลบเพื่อลบรายการ
- [ ] **3.5** ตัดราคาด้วย**คูปอง** 1 ใบ → ราคาลดถูกต้องตามเงื่อนไขคูปอง
- [ ] **3.6** **ปิดกะ** → ใส่เงินสดที่นับได้ → ระบบแสดงสรุป: เงินสดที่ควรได้ (เฉพาะออเดอร์ที่จ่ายแล้ว) vs ที่นับได้ → ผลต่างแสดงชัด
- [ ] **3.7** ปิดกะแล้วกะถูกปิดจริง (เปิดกะใหม่ได้) และประวัติกะย้อนดูได้

## 4) 🖨️ พิมพ์ใบเสร็จ + คิวครัว

> **รอบทดสอบปัจจุบัน (Owner directive 2026-10-26): ใช้ Print-to-PDF ไปก่อน** — เว้นชื่อเครื่องพิมพ์ใน print-settings → ไดอะล็อกเบราว์เซอร์ → เลือก "บันทึกเป็น PDF" · ข้อมูลทดสอบอยู่ที่ **local Supabase** · **เครื่องพิมพ์จริง = แอดมินจะตามเพิ่มให้ทีหลัง** (ข้อ 4.1 "กระดาษออกมาจริง" = รอบเครื่องจริง · ข้อ 4.2–4.6 ตรวจด้วย PDF ได้เลย)

- [ ] **4.1** (รอบเครื่องจริง — รอแอดมินเพิ่มเครื่อง) เข้า `/admin/print-settings` → เลือกเครื่องพิมพ์ (ผ่านหน้าต่างพิมพ์ของเครื่อง) → กด **"พิมพ์ทดสอบ"** → กระดาษออกมาจริง
- [ ] **4.2** ออเดอร์ใหม่ทุกใบ (ทั้ง PWA และ POS) **เข้าคิวพิมพ์อัตโนมัติ** เห็นใน "คิวพิมพ์" บนหน้า POS
- [ ] **4.3** กดพิมพ์ใบเสร็จ → เลือกเครื่องพิมพ์ → **กดยืนยันว่า "พิมพ์แล้ว"** → สถานะเปลี่ยนเป็น `พิมพ์แล้ว`
- [ ] **4.4** **ข้อสำคัญ:** ถ้าไม่กดยืนยัน สถานะต้องค้างที่ `ส่งแล้ว` (ไม่แอบอ้างว่าพิมพ์สำเร็จ)
- [ ] **4.5** ทดสอบ "พิมพ์ซ้ำ" เมื่อเครื่องพิมพ์ออฟไลน์ → ระบบไม่พัง + ออเดอร์ไม่หาย + พิมพ์ซ้ำได้
- [ ] **4.6** ใบเสร็จแสดง: เลขออเดอร์ วันที่ รายการสินค้า+ตัวเลือก ราคารวม ค่าจัดส่ง(0 สำหรับ pickup) ภาษี/ส่วนลด ช่องทางขาย (POS/PWA)

## 5) 📊 ปิดยอดรายวัน + Export CSV

- [ ] **5.1** เข้า `/admin/reports` → เลือกวันนี้ → เห็น: ยอดขายรวม / ยอดที่**จ่ายแล้ว** / **ค้างชำระ** / **คืนเงินแล้ว** แยกกันชัดเจน
- [ ] **5.2** ยอดแยกตามช่องทางชำระ (เงินสด/โอน/บัตร) และแยกออเดอร์ "รับที่ร้าน" ออกมา
- [ ] **5.3** กด **"ปิดยอดประจำวัน"** → ระบบบันทึกยอดปิด (กดซ้ำได้โดยไม่สร้างรายการซ้ำ)
- [ ] **5.4** กด **Export CSV** → เปิดใน Excel ภาษาไทยไม่เพี้ยน (มี BOM) — ยอดในไฟล์ตรงกับหน้าจอ
- [ ] **5.5** (กติกา) รายงาน**ไม่แสดง "กำไร"** เพราะต้นทุนยังไม่ครบ — ถ้าเห็นตัวเลขกำไรที่ไหนให้รายงานเป็นบั๊ก

## 6) 💳 ชำระเงินออนไลน์

- [ ] **6.1** สั่ง PWA แบบ **PromptPay QR** → QR แสดง → ชำระ → อัปโหลดสลิป → แอดมิน**อนุมัติสลิป** → สถานะเป็น paid
- [ ] **6.2** ทดสอบสลิปปลอม/ผิดจำนวน → แอดมินปฏิเสธได้ + สถานะไม่เปลี่ยนเป็น paid
- [ ] **6.3** (ถ้าเปิดใช้ Stripe) จ่ายด้วยบัตร test → สำเร็จ + เห็นใน payment history
- [ ] **6.4** ปุ่ม "คัดลอกเลขที่บัญชี/ยอด" ทำงาน และหน้าชำระแสดงยอดตรงกับออเดอร์

## 7) 🛠️ ระบบหลังบ้านอื่น ๆ (ตรวจอย่างละ 1 ครั้ง)

- [ ] **7.1 เมนูสินค้า:** เพิ่ม/แก้/ปิดการขายสินค้า + ตัวเลือก/ราคา + รูปสินค้า (แคชรูปทำงาน: แก้รูปแล้วหน้าเว็บอัปเดต)
- [ ] **7.2 คูปอง:** สร้างคูปอง % / ลดบาท / ขั้นต่ำยอดสั่ง / จำกัดจำนวนครั้ง → ใช้ได้จริงและหมดอายุจริง
- [ ] **7.3 ออเดอร์:** ค้นหา/กรองตามสถานะ+วันที่ · ดูประวัติสถานะย้อนหลัง · หมายเหตุลูกค้า/พนักงานแสดงครบ
- [ ] **7.4 ไรเดอร์:** เพิ่มไรเดอร์ → มอบหมายออเดอร์ → ไรเดอร์อัปเดตสถานะ+รูปส่งมอบ → แอดมินเห็นรูป
- [ ] **7.5 คอนเทนต์/อนุมัติ:** ส่งคอนเทนต์พร้อมรูป+มาสคอต → อนุมัติ/ปฏิเสธ → แสดงผลถูกต้อง
- [ ] **7.6 รีวิว:** ลูกค้าให้ดาว+คอมเมนต์ → แอดมินซ่อน/แสดง → ดาวเฉลี่ยถูกต้อง
- [ ] **7.7 แจ้งเตือน:** ออเดอร์ใหม่/สถานะเปลี่ยน → LINE/แจ้งเตือนในระบบทำงาน (เท่าที่ตั้งค่าไว้)
- [ ] **7.8 AI แชท/สั่งอาหารด้วยเสียง:** ถามเมนู/สั่งอาหารผ่านแชท → สร้างตะกร้าได้จริง
- [ ] **7.9 สมาชิก/OTP:** สมัคร/เข้าสู่ระบบด้วย OTP มือถือ → ข้อมูลลูกค้าเดิม (ที่อยู่/ประวัติ) ยังอยู่
- [ ] **7.10 PWA/มือถือ:** ติดตั้ง PWA ได้ · เปิดในมือถือหน้าจอเล็กทุกหน้าไม่ล้น · แคชรูป/ฟอนต์ทำงาน (รูปเมนูไม่หาย)

## 8) ☁️ Backup อัตโนมัติ (ทดสอบ 1 ครั้ง)

- [ ] **8.1** GitHub → Actions → **daily-backup** → กด **Run workflow** (mode: backup) → รอผลเป็น**สีเขียว**
- [ ] **8.2** เข้า Supabase Dashboard → Storage → **db-backups** (ต้องเป็น Private) → เห็นไฟล์ `db/bmb-db-YYYYMMDD-HHMMSS.sql.gz`
- [ ] **8.3** กด Run workflow อีกครั้ง (mode: verify) หรือดู step "verify" ใน run เดิม → ขึ้น `VERIFY OK`
- [ ] **8.4** (กติกา) บั๊กเดียวที่ยอมรับไม่ได้คือ "backup ขาดโดยไม่มีใครรู้" — ถ้า run ล้ม ต้องเห็นการแจ้งเตือน (GitHub/LINE)

## 📌 กติกาข้อมูลระหว่างทดสอบ (กันดูตัวเลขผิด)

1. **ยอดขาย ≠ เงินสดที่ได้** — ให้เทียบเฉพาะออเดอร์สถานะ "จ่ายแล้ว" เท่านั้น
2. **เงินสดปิดกะ** ต้องเท่ากับผลรวมออเดอร์เงินสดที่ "จ่ายแล้ว" ในช่วงกะ (± ที่ใส่ float ตอนเปิดกะ)
3. **สถานะพิมพ์** 4 ระดับ — เครื่องพิมพ์ไม่ทำงาน ≠ ออเดอร์หาย
4. **Pickup = ค่าจัดส่ง 0** เสมอ (นโยบาย Owner) — ถ้าเห็นค่าส่งปน ให้แจ้งทันที
5. **ปิดยอดรายวัน** กดซ้ำได้โดยไม่สร้างรายการซ้ำ (idempotent)

> เจอจุดผิดปกติ: จด **เวลา + หน้า + เลขออเดอร์ + ภาพหน้าจอ** → ส่งให้ AI แก้ต่อได้ทันที
