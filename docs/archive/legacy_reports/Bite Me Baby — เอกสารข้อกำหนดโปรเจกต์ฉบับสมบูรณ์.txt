5.3 Self vs External Decision
text
Order placed
    ↓
Calculate distance from kitchen
    ↓
> 5 km? → EXTERNAL PROVIDER
    ↓
≤ 5 km?
    ↓

    ↓
< 2 orders? → [Economy Check]
    → ถ้าคุ้ม (margin > delivery cost) → SELF
    → ถ้าไม่คุ้ม → EXTERNAL
    ↓
≥ 2 orders? → SELF
    ↓

    → Driver available → SELF
    → Driver not available → EXTERNAL
    ↓
Final decision → SELF / EXTERNAL

5.5 Route Optimization Logic
text
Input:
  - Kitchen location (origin)
  - List of orders (destinations)
  - Each order: { id, lat, lng, ready_time, delivery_window }

Step 1: Fetch driving distances + times (Google Distance Matrix)
Step 2: Sort by readiness (ready_time ascending)
Step 3: Apply time window constraints
Step 4: Solve TSP with heuristics
Step 5: Return optimized sequence

Algorithm: 
  - Nearest Neighbor (fast, < 10 orders)
  - OR-Tools (Google) for optimal (> 10 orders)
5.6 Weighted Optimization
text
Cost = α × distance + β × waiting_time + γ × window_penalty

α = 0.4 (distance weight)
β = 0.4 (waiting time weight)
γ = 0.2 (window penalty weight)

text

  → กด "ส่งสำเร็จ"

  → รอ 5 นาที

  → ส่งต่อรอบเย็น / กลับร้าน

  → สาเหตุ (ที่อยู่ผิด, ไม่มีคนรับ)
  → ระบบแจ้ง admin
  → ต้องจัดการคืนเงิน / re-delivery

9. PRE-ORDER SYSTEM (สั่งล่วงหน้า)
9.1 Features
text
✅ สั่งล่วงหน้าได้สูงสุด 7 วัน
✅ เลือกรอบ (เช้า/เที่ยง/เย็น) + วันที่ต้องการ
✅ ระบบตรวจสอบกำลังการผลิตของครัว (Kitchen Capacity)
✅ ระบบตรวจสอบวัตถุดิบเพียงพอไหม (Inventory Check)
✅ แจ้งเตือนเมื่อรอบนั้นเต็ม (Capacity Full)
✅ สร้าง Pre-order Queue ให้ครัวเห็นล่วงหน้า
✅ แจ้งเตือนครัวล่วงหน้าเพื่อเตรียมวัตถุดิบ
✅ ลูกค้าสามารถดู/แก้ไข/ยกเลิก Pre-order ได้
9.2 Pre-order Flow
text
1. ลูกค้าเลือกเมนู
2. เลือกวันที่ + รอบ
3. ระบบตรวจสอบ Capacity
4. ระบบตรวจสอบ Inventory
5. ถ้าผ่าน → จอง Pre-order
6. ครัวเห็น Pre-order ใน Queue
7. ครัวเตรียมวัตถุดิบล่วงหน้า
8. วันที่ถึง → Pre-order เปลี่ยนเป็น Order
9. ดำเนินการตามรอบปกติ

11.2 Pre-order Tables
sql
-- pre_orders
CREATE TABLE pre_orders (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  customer_id uuid REFERENCES customers(id) NOT NULL,
  round_type text NOT NULL CHECK (round_type IN ('morning', 'midday', 'evening')),
  delivery_date date NOT NULL,
  items jsonb NOT NULL,
  status text DEFAULT 'reserved' CHECK (status IN ('reserved', 'confirmed', 'preparing', 'ready', 'delivered', 'cancelled')),
  kitchen_capacity_used integer DEFAULT 0,
  total_amount integer DEFAULT 0,
  notes text,
  reserved_at timestamp DEFAULT now(),
  confirmed_at timestamp,
  converted_at timestamp,
  created_at timestamp DEFAULT now(),
  updated_at timestamp DEFAULT now()
);

-- kitchen_capacity
CREATE TABLE kitchen_capacity (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  round_type text NOT NULL CHECK (round_type IN ('morning', 'midday', 'evening')),
  date date NOT NULL,
  max_orders integer DEFAULT 20,
  current_orders integer DEFAULT 0,
  pre_orders_count integer DEFAULT 0,
  prep_time_buffer_minutes integer DEFAULT 15,
  is_holiday boolean DEFAULT false,
  notes text,
  created_at timestamp DEFAULT now(),
  updated_at timestamp DEFAULT now(),
  UNIQUE(round_type, date)
);

-- pre_order_items
CREATE TABLE pre_order_items (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  pre_order_id uuid REFERENCES pre_orders(id) ON DELETE CASCADE,
  menu_item_id uuid REFERENCES menu_items(id),
  quantity integer DEFAULT 1,
  unit_price integer DEFAULT 0,
  total_price integer DEFAULT 0,
  notes text,
  created_at timestamp DEFAULT now()
);

17.1 เป้าหมาย
text
ปรับปรุงการจัดการรูปภาพและหน้าตา UI บนหน้า PWA (Home/Menu)
ให้เป็นสไตล์ "3D Floating Visual Layout" ที่มีภาพอาหารและไอคอนลอยนูน
มีแอนิเมชันตอบสนอง และใช้ระบบอัตโนมัติแปลงภาพถ่ายจากร้านจริง
ให้เป็นภาพโปรดักชันสตูดิโอเดียวกันโดยใช้ OpenRouter API

17.2 Image Production Pipeline (หลังบ้าน)
text
ภาพถ่ายร้านจริง (อาหารในกล่องบรรจุภัณฑ์)
    ↓
OpenRouter Image Endpoint (Image-to-Image — ใช้ภาพเดิมเป็น Input Reference)
    ↓
ลบกล่อง/ฝาพลาสติก/ช้อน + รักษาเนื้ออาหารจริง 100% (Character Consistency:
กุ้งสด / ไข่กุ้ง / หมูสามชั้นลวก ห้ามเปลี่ยนหรือเติมวัตถุดิบใหม่)
    ↓
เรนเดอร์ลงกล่องอาหารคราฟท์บอกซ์ + กล่องอาหาร PP สีดำ (ตามชุดตัวอย่างที่อนุมัติ)
    ↓
มุมกล้องเฉียง 45 องศา (Isometric) + โทนแสง Vivid Warm Studio Soft-box
    ↓
พื้นหลังสีขาวล้วน → แปลงเป็นไฟล์โปร่งใส .WebP
    ↓
PWA Fast App Shell (Home/Menu)

17.3 Model Configuration (OpenRouter — config ผ่าน env ห้าม hardcode)
text
VITE_OPENROUTER_API_KEY              : key เดิมของโปรเจกต์ (ย้ายจาก aiService.ts เข้า .env)
VITE_OPENROUTER_IMAGE_MODEL          : google/nano-banana-2-lite (โมเดลหลัก ประหยัด/คุ้มค่า)
VITE_OPENROUTER_IMAGE_MODEL_FALLBACK : bytedance/seedream-4.5 (โมเดลสำรอง)

17.4 3D Floating UI Specification
text
- Layering  : ภาพอาหารเหลื่อมหลุดจากขอบบนการ์ด (Negative Margin -mt-6 / -mt-8)
- Depth     : CSS filter drop-shadow ซ้อนเลเยอร์ (Soft UI / Glassmorphism)
              ⛔ ห้ามใช้ box-shadow บนรูปอาหารเด็ดขาด
- Surface   : การ์ดกระจกฝ้า (translucent + backdrop-blur)
- Token     : ใช้สีแบรนด์เดิม #F97316 / #FBBF24 / #FFF7ED / #92400E

17.5 Micro-interactions Animation
text
Hover/Touch ภาพอาหาร : group-hover:-translate-y-4  group-hover:scale-105
กด/แตะ การ์ด         : group-active:scale-[0.99] + เงาฟุ้งกระจาย
Timing               : duration-300 / ease-out + will-change-transform
Accessibility        : เคารพ prefers-reduced-motion, touch target >= 44px

17.6 Business Rules Enforcement
text
- ปุ่ม "Same-day Order" (สั่งเลยวันนี้) แสดงผลเมื่อ products.is_available = true
  ผ่านระบบ Live Availability Engine เท่านั้น
  (AVAILABLE / LIMITED / SOLD_OUT / TEMPORARILY_UNAVAILABLE / STORE_CLOSED /
   DELIVERY_UNAVAILABLE) — ถ้าขายไม่ได้ปุ่มต้องไม่ถูก render
- ปุ่ม "Pre-order" (จองล่วงหน้า) เปิดให้เลือกส่งตามรอบการผลิต (Delivery Round:
  morning / midday / evening / future batch)
- ทั้งสองปุ่มต้องแยก Action และเก็บ Log แยกกันเด็ดขาด (append-only,
  orderMode = 'same-day' / 'pre-order', หนึ่งการแตะห้ามเกิดสอง log)
- Props ของ FoodMenuCard ต้อง Type-safe — ห้ามใช้ any
